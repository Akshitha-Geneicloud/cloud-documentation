#  **1. What Are Logs in AWS?**

Logs are records of events happening inside your AWS environment. They help you:

-   Understand system behavior
    
-   Troubleshoot problems
    
-   Monitor security
    
-   Audit what happened and when
    

AWS stores most logs in **Amazon CloudWatch Logs**.

----------

#  **2. Types of Logs in AWS **

## **(A) Application Logs**

These are logs generated by apps running on EC2, Lambda, ECS, EKS, etc.

-   Examples: errors, API requests, user activity.
    

**Scenario:**  
My chatbot running on EC2 starts showing “500 Internal Server Error”. By checking **application logs** pushed to CloudWatch, we find the JavaScript file is failing to load due to CORS issues.

----------

## **(B) System Logs (OS Logs)**

These come from the operating system:

-   `/var/log/syslog`
    
-   `/var/log/messages`
    
-   SSH login logs
    
-   Kernel logs
    

**Scenario:**  
The EC2 instance becomes slow. Checking system logs shows high CPU usage caused by a background process.

----------

## **C) Web Server Logs**

Generated by servers like:

-   Nginx (`/var/log/nginx/access.log`)
    
-   Apache (`/var/log/apache2/access.log`)
    

**Scenario:**  
The website is very slow. In Nginx access logs, we can see thousands of requests from the same IP — a possible DDoS attempt.

----------

## **(D) CloudTrail Logs**

Tracks **who did what** in your AWS account.  
It records:

-   Console logins
    
-   API calls
    
-   IAM role usage
    
-   Resource changes
    

**Scenario:**  
An EC2 instance gets terminated unexpectedly. CloudTrail logs show an IAM user accidentally terminated it at 3:13 PM.

----------

## **(E) VPC Flow Logs**

These capture **network traffic information** from:

-   VPC
    
-   Subnets
    
-   ENIs (Elastic Network Interfaces)
    

A Flow Log entry tells you:

-   Source IP
    
-   Destination IP
    
-   Protocol
    
-   Action (ACCEPT/REJECT)
    

**Scenario:**  
Your EC2 cannot connect to RDS. VPC Flow Logs show traffic is **REJECTED**, meaning your security group is blocking it.

----------

## (F) Load Balancer Logs 

Load balancer generate **access logs** containing:

-   Client IP
    
-   Target
    
-   Response codes
    
-   Latency
    

**Scenario:**  
A customer complains your web app is slow. ALB logs show that many requests took **2 seconds** to respond — pointing to backend performance issues.

----------

## (G) S3 Access Logs

Tracks:

-   Who accessed an object
    
-   What operation they performed (GET, PUT, DELETE)
    

**Scenario:**  
A file inside S3 was suddenly deleted. S3 logs show exactly which IAM user deleted it.

----------

#  **3. VPC Flow Logs **

VPC Flow Logs record the _network traffic metadata_ for your resources.  
It **does NOT** store packet content but stores only information.

### **Where can you enable Flow Logs?**

-   Entire VPC
    
-   Specific subnet
    
-   Specific EC2 network interface
    

### **Flow Log contains fields like:**

-   Source IP
    
-   Destination IP
    
-   Port
    
-   Protocol
    
-   Bytes transferred
    
-   ACCEPT / REJECT
    

----------

### **Why Do We Use VPC Flow Logs?**

-   Troubleshoot connectivity
    
-   Identify blocked traffic
    
-   Detect suspicious activity
    
-   Audit network access
    

----------

### **AWS Scenarios:**

### **Scenario 1: EC2 Cannot Reach Database**

Flow Logs show:

`REJECT  Src:  EC2  IP  Dest:  RDS  IP  Port:  3306` 

This means the security group for RDS is blocking port 3306.

----------

### **Scenario 2: Detect a Security Attack**

Flow logs show many REJECTED requests from the same IP → indicate a brute-force attempt.

----------

### **Scenario 3: Unexpected Data Transfer**

You find large ACCEPT entries going to unknown IPs → possible data exfiltration.

----------

#  **4. Monitoring in AWS **

Monitoring means continuously observing the health and performance of your AWS services using **CloudWatch**.

### **CloudWatch monitors:**

-   CPU utilization
    
-   Disk read/write
    
-   Network activity
    
-   Application logs
    
-   Custom metrics
    

----------

### **CloudWatch Alarms**

Alarms trigger alerts when something crosses a threshold.

----------

### **AWS Monitoring Scenarios:**

### **Scenario 1: CPU Spikes**

Alarm sends SMS/email when EC2 CPU > 80%.

### **Scenario 2: Low Free Disk Space**

Automatically attach a bigger EBS volume using an automated action.

### **Scenario 3: Website Down**

Health check fails → CloudWatch notifies SNS → sends alert.

----------

#  **5. Resource Monitoring**

Resource Monitoring means tracking:

-   EC2
    
-   RDS
    
-   DynamoDB
    
-   Lambda
    
-   S3
    
-   Load Balancers
    

AWS automatically provides many metrics.

----------

## **EC2 Resource Monitoring**

Tracks:

-   CPU
    
-   Disk I/O
    
-   Network packets
    
-   Status checks
    

**Scenario:**  
EC2 passes “System Status Check Failed” → meaning hardware or hypervisor issue.

----------

## **S3 Monitoring**

Uses:

-   S3 Storage Metrics
    
-   S3 Request Metrics
    

**Scenario:**  
Sudden spike in S3 requests → indicates a script or bot has started hitting your bucket.

----------

## **Load Balancer Monitoring**

ALB metrics include:

-   HealthyHostCount
    
-   TargetResponseTime
    
-   4XX / 5XX errors
    

**Scenario:**  
TargetResponseTime increases to 2 seconds → backend servers are overloaded.
